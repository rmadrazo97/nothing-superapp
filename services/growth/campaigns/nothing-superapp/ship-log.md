## 2026-08-14 — `native-feel` skill v0.1 shipped to PromptVM Build Kit — one strict pass turns any web/PWA into a mobile-native-feeling app across React / Vue / Svelte / Angular / vanilla.

Fifth entry in the Build Kit (after `stack-architect`, `design-system-builder`, `dev-loop`, `explain`) — but the first framework-agnostic skill in the set. Everything else in the Kit assumes a specific harness or opinion; `native-feel` deliberately doesn't. It's CSS + HTML + minimal vanilla JS across 30 recipes, each shaped as **DETECT (grep command) → FIX (copy-paste code) → VERIFY (behavior on real hardware)**. Six categories: foundation (viewport / theme-color / manifest / apple-touch-icon / status-bar-style / maskable icons), tap-and-hover (kill gray flash, gate `:hover` in `@media (hover: hover) and (pointer: fine)`, `touch-action: manipulation`, scoped `user-select: none`), layout-and-viewport (`100dvh` / `100svh` / `100lvh` replacing `100vh`, `env(safe-area-inset-*)` on notch + home indicator), inputs-and-keyboard (16px minimum font-size to kill iOS zoom, `visualViewport` focus-scroll, `-webkit-text-size-adjust: 100%`, correct `type`+`inputmode` per field, `autocorrect="off"` on usernames), scroll-and-gestures (`overscroll-behavior: contain` scoped to sheets, `touch-action: pan-x` on horizontal carousels, iOS-safe `position: fixed + top: -scrollY` body scroll lock, remove deprecated `-webkit-overflow-scrolling: touch`), media (`muted+playsinline+autoplay` for background video, width/height on all `<img>` for zero CLS), PWA polish (iOS splash screens, `/offline` fallback SW, `format-detection: telephone=no`, `start_url + scope + id` alignment, `shortcuts` + `share_target`).

**Non-negotiable rules baked into SKILL.md.** (1) Every fix must have DETECT + FIX + VERIFY — no hand-waving. (2) Framework-agnostic: never write "the React way" — CSS + HTML + vanilla JS only, placed in whichever globals file the audit finds. (3) Zero new dependencies. (4) Detect before fix — grep first; skip recipes that don't apply; report skipped-and-why. (5) Merge, never overwrite — sentinel-block appends in globals.css, MERGE strategy in manifest.json. (6) Test-on-hardware IS the deliverable — `verify.md` is a first-class artifact; the pass is not signed off until the human runs the checklist on real iOS + real Android. (7) Accessibility never regresses — reject any "fix" that breaks a11y (no `user-scalable=no`, no global `user-select: none`); use the safe alternative (`font-size: 16px`, scoped selectors) even when it's uglier.

**The audit script (`scripts/audit.mjs`, zero deps, Node ≥ 18)** runs every DETECT grep in one shot and writes `docs/native-feel/<date>/audit.md` with FOUND / NOT PRESENT / ALREADY FIXED / UNKNOWN per recipe. Smoke-tested against `apps/web` at build time — 17 FOUND / 6 NOT PRESENT / 3 ALREADY FIXED / 4 UNKNOWN. So the moment the skill was published, we had a ready-to-execute polish backlog for the Nothing Superapp itself: no dark-mode theme-color, no apple-mobile-web-app-title, `100vh` still in a dozen places, no `touch-action: manipulation` on interactives, no `visualViewport` focus-scroll for the iOS keyboard, no `overscroll-behavior` scoping on modals, no iOS splash screens, no manifest `start_url + scope + id`, no `format-detection` meta. The kind of long-tail polish that never gets its own ticket because none of it is a "bug" — the site works — but together they're the difference between "web app on my phone" and "feels like an app on my phone."

**Drop-in reference files (`references/`)**: `head-baseline.html.txt` (all required meta tags with `{{...}}` placeholders + per-framework placement notes for Next.js App Router, Nuxt 3, SvelteKit, Astro, Vue, Angular, vanilla), `global-css-baseline.css.txt` (root reset + interactive rules + safe-area helper classes + reduced-motion honoring, all inside a `/* native-feel: mobile baseline */ … /* /native-feel */` sentinel so future runs are idempotent), `manifest-baseline.json.txt` (full PWA manifest with `display: standalone`, both `any` and `maskable` icon variants, `shortcuts`, `screenshots`, `id + scope + start_url` alignment). Plus `audit-recipes.txt` (the 30 DETECT/FIX/VERIFY blocks, 39KB), `verification-checklist.txt` (device tests grouped by iOS + Android + cross-device a11y, with a "how to report ❌s" section for the copy-paste feedback loop), and `recipe-index.txt` (one-line-per for scanning).

**Published:** PromptVM `nothing-superapp/skills` directory as slug `native-feel-caf91d7d` — installed locally at `~/.claude/skills/native-feel-caf91d7d/` and visible in the harness's available-skills manifest. Bundle body 18KB. Reference doc + how-to-bump recipe updated in `reference_promptvm_workspace_ids.md`. Source of truth stays in `skills/native-feel/` on-disk; future updates go through `python3 build_bundle.py … && promptvm prompts versions create <id> -f …` to preserve version history. This is skill #5 in the Kit — the first one that promises portability across every web framework, not just Next.js.

## 2026-08-10 — Reminders + agent loops — Nothing Superapp's answer to Claude loops. A reminder can be a notification OR an autonomous copilot prompt that runs on a schedule. Weekly meal review, gym adherence check, grocery list from the active plan — set once, get a push when the agent's done.

Ships a standalone Reminders mini-app whose killer feature isn't the reminders themselves — it's that a reminder can be an autonomous copilot loop. Pick `◐ AGENT LOOP` when creating a reminder, type a prompt like _"Review my calorie adherence this week and give me 3 concrete adjustments"_, pick weekly Sunday 20:00, save. Every Sunday at 20:00 the same 43-tool copilot the interactive chat uses runs your prompt end-to-end (search_foods, get_daily_summary, calorie_lite_entries_list — the whole surface), and you get a push notification with the answer sitting in `/app/reminders?tab=history`. Set it once. Never think about it again.

**Infra (migration 017 + Zod).** `reminders` (id, user_id, title, notes, kind check in ('notify','agent_loop'), schedule_kind check in ('once','daily','weekly','monthly','cron'), per-shape columns (schedule_at, schedule_time, schedule_dow int[], schedule_dom, schedule_cron), timezone, agent_task jsonb, push_topic default 'reminders', active, last_fired_at, next_fire_at, timestamps + updated_at trigger). Owner-only RLS + partial index `on (user_id, next_fire_at) where active` + a global `on (next_fire_at) where active` for the tick handler's due-scan. `reminder_runs` (id, reminder_id, user_id, fired_at, kind, status check in ('ok','error','skipped'), agent_summary, agent_thread_id → copilot_threads on delete set null, push_sent, error_message). Applied to prod via `psql` in ~1s. Zod in `packages/shared/src/schemas/reminders.ts` mirrors the shape with cross-field `.superRefine()`: `once` needs schedule_at, `daily` needs schedule_time, `weekly` needs both time + dow[], `monthly` needs dom, `cron` needs the raw expression, `agent_loop` needs agent_task.prompt. All add-only exports through `packages/shared/src/schemas/index.ts` — zero drift with the two parallel workers.

**Schedule engine (`packages/shared/src/reminders-next-fire.ts`, zero deps).** `computeNextFireAt(schedule, from)` returns the next UTC ISO for any schedule kind. Timezone-aware via `Intl.DateTimeFormat` — "daily 08:00 America/Mexico_City" resolves correctly across DST. Cron parser is a permissive 5- or 6-field POSIX impl (m h dom mon dow with `*`, `*/step`, `val-val`, `val,val,val`) — advances minute-by-minute bounded to 366 days. The mini-app's `resources.ts` wires a `beforeWrite` hook that computes `next_fire_at` on every create/update — the tick handler can then filter `where active and next_fire_at <= now()` on an indexed scan.

**Tick handler (`/api/reminders/tick`, GH Actions cron).** Vercel Hobby caps cron resolution at daily. Moved to GitHub Actions `.github/workflows/reminders-tick.yml` — `curl -X POST -H "authorization: Bearer $CRON_SECRET"` every 5 minutes for free with no plan constraint. Handler pulls the next 100 due reminders with `service_role`, `fireReminder()` each one: notify fires `sendPushToUser(user_id, {title, body: notes, url: '/app/reminders', tag: 'reminder-<id>'}, 'reminders')` + inserts `reminder_runs`; agent_loop kicks the loop via `after()` from `next/server` so slow Kimi calls don't blow past Vercel's 60s serverless budget. Idempotency: 60s debounce on `last_fired_at` + we always mark `last_fired_at + next_fire_at` FIRST so a mid-flight crash never re-fires the same reminder next tick. Once reminders auto-deactivate after firing.

**Agent-loop runtime (`apps/web/src/lib/ai/agent-loops.ts`).** `runAgentLoop(reminder, supabase)` calls `streamText({ model: chatModel('text'), system: <short authoritative prompt>, messages: [{role:'user', content: task.prompt}], tools: copilotTools(user_id, supabase), stopWhen: stepCountIs(max_steps ?? 5) })` and awaits `result.text` — no streaming needed, the user isn't watching. The service-role Supabase client is passed as-is; every tool in `copilotTools` internally scopes with `.eq('user_id', userId)` or forces `insert({ user_id: userId, ... })`, so RLS is structurally enforced without a session cookie. Response is capped at 2000 chars for the DB, 500 for the push preview. Errors caught + logged into `reminder_runs.error_message` so the History tab can render them.

**UI (Nothing OS aesthetic, design tokens only, no hex, no `--space-5`).** Three tabs: **UPCOMING** (active, next-fire ascending), **ALL** (includes inactive, per-row Pause/Resume chip), **HISTORY** (`reminder_runs` newest-first, agent summaries collapsible). Each row: title + schedule chip (`⏰ Daily 08:00`, `◔ Mon,Wed 19:30`, `⧗ cron · 0 */2 * * *`), a `NOTIFY` / `◐ AGENT` cadmium badge, `▶ Run now` (calls `/api/reminders/trigger` with session auth), `Pause`/`Resume`, `× Delete` (two-tap confirm). `+ NEW REMINDER` opens an inline form with kind toggle, schedule selector, timezone (browser IANA default), and — when Agent Loop is picked — a Prompt / Scope / Max steps trio. `◐ TEMPLATES` disclosure prefills 6 canned reminders: 3 notify (`Drink water every 2h` cron, `Log lunch` daily 13:30, `Weekly weigh-in` Mon 07:00) + 3 agent loops (`Weekly meal-plan review` Sun 20:00, `Gym adherence check` Sun 19:00, `Grocery list from active meal plan` Sat 10:00). Settings drawer: master `reminders` push-topic toggle + clear-history button.

**Copilot integration (4 new tools, add-only alphabetical).** `create_reminder` teaches the shape in a single description (kinds, schedule shapes, agent_task fields). `list_reminders` (read-only, filter by kind + active_only). `toggle_reminder` (pause/resume). `trigger_reminder_now` — fires a reminder synchronously and returns the agent's response inline, so `"run my weekly review now"` weaves the answer straight into the chat reply. All write-tools go through `_gate.assertEntitled + assertWriteBudget` + `_audit.insertToolAudit`. The framework's `reminders_reminders_*` and `reminders_runs_*` CRUD tools land automatically via `resourceTools()` — the hand-written tools are semantic aliases for the common flows.

**Coordination.** Migration slot 017 (015 = copilot threads, 016 = meal-entry grouping, both taken by parallel workers by the time this wave landed). Add-only extensions on `packages/shared/src/schemas/index.ts` (+ `push_topics` enum now includes `'reminders'`), `apps/web/src/lib/mini-apps/{registry,client-registry,resources-registry}.ts`, `apps/web/src/lib/ai/tools/index.ts`, `apps/web/next.config.ts` `transpilePackages`, `apps/web/package.json`. A "coordinator" agent picked up my WIP mid-flight and committed both the tick handler + agent-loops runtime + GH Actions workflow in one shot when it noticed the Vercel Hobby cron cap — nice belt-and-suspenders.

**Angle.** Open the launcher → tap ⏰ **Reminders**. Tap `+ NEW REMINDER` → `◐ TEMPLATES` → `Weekly meal-plan review` → Save. That's it. Every Sunday at 20:00 in your timezone, the copilot pulls `get_daily_summary` for each day of the past week, cross-references `calorie_lite_entries_list`, and pushes _"Under target Mon-Wed by 300kcal. Over on Sat by 500. Cut Saturday's late-night snack, front-load protein to Wed."_ straight to your lock screen. Set once, delivered forever. Follow-ups: (1) UI to browse past runs by reminder id with agent-thread deep-link into `/app/assistant?t=<uuid>`; (2) copilot "convert this chat into a scheduled loop" one-tap; (3) reminder-templates catalog surfacing (currently 6 hand-picked; the framework can hold hundreds).

## 2026-08-10 — Meal plans no longer explode into 6 rows on TODAY — one group card, expandable, delete whole meal or edit individual ingredients.

Logging a meal from your plan used to shred it into 5–7 sibling rows that drowned every manual entry you'd added that day — "chicken 150 g · rice 180 g · broccoli 100 g · olive oil 10 g · avocado 50 g · lime 5 g" stacked one after the other, no visual grouping, no way to say "actually undo that whole meal, I ate something else". This wave collapses each plan-logged meal into a single card labelled `Comida · Opción 2` with the group's total kcal + macros on the right, a chevron on the left to expand/collapse, and a two-tap `× Delete group` chip that batch-removes every row in one gesture. Expand the card and the original `EntryRow` component renders each ingredient exactly the same as before — the per-row `✎ EDIT` + `× DELETE` two-taps still work for surgical fixes ("bump the rice to 200 g", "remove the olive oil"). Groups with 3+ items default to collapsed so the day view stays scannable; the collapse state persists per group in `sessionStorage` so scrolling back doesn't re-collapse a card you'd deliberately opened.

**Infra (migration 016 + Zod).** `alter table app_calorie_entries add column meal_group_id uuid, meal_group_label text` — both nullable, no FK. Partial index `app_calorie_entries_meal_group_idx on (user_id, meal_group_id) where meal_group_id is not null` keeps the index tiny (only grouped rows are ever considered) while still supporting "give me every row in this group" in one hop for the batch-delete path. Grouping is SOFT by design: no cascade, no FK back to `meal_plans` — deleting a plan (or renaming it, or shuffling its options) never rewrites your history. The label is a snapshot at log-time so a later edit of "Comida" → "Almuerzo" doesn't retroactively re-name every historical card. Applied to prod in 3 statements via `psql`, same env pattern as `seed-foods.py`. Zod extended add-only on `calorieEntrySchema` + `calorieEntryInsertSchema` in `packages/shared/src/schemas/index.ts` — both new fields nullable + optional so every existing insert path keeps working untouched.

**Server (log-meal + copilot tool stamp the group).** `POST /api/mini-apps/calorie-lite/meal-plans/log-meal/route.ts` now calls `randomUUID()` before the batch insert, computes the label as `${meal.name_en ?? meal.name_es ?? meal.id} · Opción ${option_selected}`, and writes both fields on every ingredient row in the batch. The response echoes `meal_group_id` + `meal_group_label` so the client can render optimistically without a re-fetch. `apps/web/src/lib/ai/tools/log-meal-from-plan.ts` mirrors the exact same logic (single source of truth stays honest) and its `summary` field now reads `Logged 5 ingredients as Comida · Opción 2 (group abc12345) into lunch. Delete individual rows or the whole group card from the TODAY view.` — so when the user says "delete that meal I just logged" a turn later, the model has the group id + label sitting in its own transcript to reference. Tool description explicitly names the new fields + notes a `delete_meal_group` follow-up tool as a TODO.

**UI (bucket + MealGroupCard).** `EntryList` in `apps/mini-apps/calorie-lite/page.tsx` now runs a `bucketEntries()` pass that partitions rows into `{kind:'solo'}` (rendered by the untouched `EntryRow`) and `{kind:'group'}` (rendered by the new `MealGroupCard`). Bucket order is driven by the newest row inside each bucket, so a freshly-logged meal jumps to the top of TODAY same as before. Two-tap confirm auto-disarms after 3s (mirrors the existing `EntryRow` delete pattern), loops row-by-row through the framework `DELETE /api/mini-apps/calorie-lite/resources/entries/[id]` endpoint (no batch endpoint yet — simple, honest, tomorrow's `delete_meal_group` tool can replace with a single call), and fires `calorie_entry_added` on the events bus so totals + streak + insights refresh in the same tick. `EntryRow` component signature stays UNTOUCHED — the wrapping is entirely in `EntryList` + the new card, so every existing behaviour (edit, delete, expand-for-actions) keeps working when you drill into a group.

## 2026-08-10 — Copilot rebuilt into a proper AI chat — threads, streaming cursor, message actions, multi-line composer.

The assistant stopped feeling like a demo and started feeling like the real thing. The `/app/assistant` surface was a single ephemeral session — refresh the page and everything you'd asked was gone; the user's own messages didn't render on some frames; tokens landed in silence with a static "Thinking…" line and no cursor; the composer had two ALL-CAPS chip buttons (`IMG` / `MIC`) elbowing the textarea. This wave rebuilds it end-to-end: **persistent threads** (owner-only, soft-deletable), **left slide-in threads drawer** with rename + delete + relative timestamps, **URL-bound thread state** (`?t=<uuid>`, deep-linkable + browser-back friendly), **streaming ▊ cursor** that trails the live token stream, **message actions** (Copy / Regenerate / Continue) on hover under every assistant bubble, **auto-scroll-only-when-at-bottom** with a `↓ NEW` chip when the user reads back, **markdown-lite** (bold / italic / code / lists / quotes / links, no new dep), and **icon-only round composer buttons** with a cadmium send circle that flips to a spin-glyph while streaming.

**Threads infra (migration 015 + REST + persist-on-finish).** New `copilot_threads` (id, user_id, title, context, last_message_at, archived_at + trigger, RLS) + `copilot_messages` (id, thread_id, user_id, role check-enum, `parts` jsonb, created_at + RLS). Applied to prod in 2.0 seconds; both tables land with 4 owner-only policies each. Zod schemas re-exported from `@nothing/shared` via `copilot-thread.ts` with `deriveThreadTitle()` that trims + truncates to 60 chars for auto-titling. Three new REST endpoints: `POST/GET /api/copilot/threads` (create + list, most-recent-first, archived excluded, capped at 100); `GET/PATCH/DELETE /api/copilot/threads/[id]` (hydrate + rename + soft-delete). `/api/copilot POST` now accepts optional `thread_id` in the body — when present + owned, `streamText`'s `onFinish` upserts the fresh user turn + assistant response messages into `copilot_messages`. Assistant `response.messages` get flattened into UIMessage-shaped `parts` (text + reasoning + `tool-*` with matched `tool-result` → `output`) so rehydration renders text, reasoning, AND tool cards identically to the live stream. Auto-titles the thread the first time it's still called "New chat" using the first user message text. Persistence is opt-in — clients that don't send `thread_id` keep the old ephemeral behaviour, so the in-app calorie-lite drawer (single-session by design) needs zero changes.

**Client (drawer + URL binding + rehydration).** New `ThreadDrawer` slides in from the left at `width: min(320px, 85vw)`, dark surface, `boxShadow: 12px 0 32px rgba(0,0,0,.6)`, safe-area-left + safe-area-top padding, backdrop tap + Escape close, body-scroll lock while open. Header row shows `⚙ THREADS` + `×` close; body has a cadmium `+ NEW CHAT` chip and a scrollable list where each row shows the title (Space Grotesk, ellipsis at 1 line) + a relative timestamp ("just now" / "5m ago" / "2h ago" / "3d ago" / "Aug 10 · 14:30"). Per-row `⋯` reveals an inline menu with Rename (autofocus inline `<input>`, Enter commits, Escape cancels) and `× Delete` (two-tap confirm that auto-cancels after 3s). Active row picks up a `border-left: 2px solid var(--color-accent)` + a subtle raised background. Header on the standalone page: `☰` (hamburger, opens the drawer) · `◐ COPILOT` · `+` (new chat, clears `?t=`).

## 2026-08-09 — Mini-App Resource Framework (declare-once REST + copilot tools + client hooks)

Mini-apps stopped hand-writing 400 lines of Supabase-plus-Zod-plus-fetch plumbing per data type. They now declare a `resources.ts` and get the whole data layer for free.

**Declaration.** Each mini-app exports a `MiniAppResourceModule` — a slug + an array of `MiniAppResource`s. Each resource carries the Postgres table, the row/insert/update Zod schemas from `@nothing/shared`, an ops matrix (list/get/create/update/delete — opt-in for writes), a `filterableColumns` whitelist, and an `agent` block with the description the LLM sees.

**REST (generic).** New routes at `/api/mini-apps/[slug]/resources/[resource]` + `.../[id]` back every declared resource with auth (401) + entitlement (402) + rate-limit (300 read/hr, 30 write/hr) gates. Server-owned columns (`id`, `user_id`, `created_at`, `updated_at`, `entered_at`, `started_at`, `ended_at`) are stripped from every insert/update; `user_id` is FORCED from the session. Existing hand-written routes at `/api/mini-apps/<slug>/<name>` are untouched — the two coexist until a later wave collapses the hand-written ones onto the framework.

**Copilot tools (auto).** `apps/web/src/lib/ai/resource-tools.ts` walks every mini-app's resources and emits named tools (`calorie_lite_entries_list`, `calorie_lite_water_create`, `pomodoro_sessions_list`, etc.) using each resource's Zod schema as the tool input schema. Tools share the existing 10-write/hr copilot budget + entitlement re-check, so the LLM can't route around the tighter budget via REST. When the parallel copilot worker's route wires up its tools map, one line: `{ ...handTools, ...resourceTools(userId, supabase) }`.

**Client hook.** `useResource(slug, resource)` in `@nothing/mini-apps-runtime` fetches list + exposes `{ data, isLoading, error, create, update, remove, refetch }`. Zero new deps — plain fetch + React.

**Canary.** Calorie Lite declares 7 resources (entries, water, weight-entries, custom-foods, custom-meals, favorites, foods read-only). Pomodoro declares 1 (sessions). That's 32 auto-generated copilot tools before the copilot worker ships their own (`calorie_lite_entries_list`, `calorie_lite_entries_create`, `calorie_lite_water_delete`, `pomodoro_sessions_list`, …).

**Angle.** Adding a mini-app used to mean writing REST by hand, writing copilot tools by hand, and writing client fetch by hand — three code paths, three sets of Zod schemas, three chances to leak `user_id` from the client. Now every mini-app is a declaration. The next mini-app author writes a `resources.ts` file and gets a full data layer + agent surface without touching route handlers or tool factories. Follow-up wave: collapse the hand-written calorie-lite routes onto the framework and delete ~1200 lines of duplicate plumbing.

**Gotcha caught.** First iteration used `_resources/` for the path segment; Next.js treats underscore-prefixed folders as private and silently 404'd the routes. Renamed to `resources/` — noted in the framework README so nobody else re-learns that.
