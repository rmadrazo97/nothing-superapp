**Shipped:** 2026-08-11

## What shipped

### Gym PROGRESSION tab (first PixelUI dogfood outside the assistant)
- Route: `/app/gym-routine/progression`
- KPI grid (4): Volume (kg lifted), Sets, PRs (top-set > previous max), Sessions — each with a 4-week delta vs the prior 4 weeks.
- Volume-per-week trend line (8 weeks).
- Per-exercise progression: top-4 most-logged exercises in the last 30 days, each with an 8-session top-set trajectory.
- Empty state (no sessions in 90d): "Log a few sessions and the numbers will show up here."

Design: same PixelUI atoms as the assistant's `render_*` panels — 3px cell + 1px gap grid, Doto numerals, Space Mono labels, 2×2 cadmium LED cluster top-right of every card. Reads as one instrument suite with the assistant surface.

Aggregation: pulls 120 days of finished `workout_sessions`, computes rolling 4-week window vs prior 4-week window for volume + sets. PR detection: walks sessions ascending per exercise, "PR" fires only if the exercise has been logged before (prevents "first-ever session = 12 PRs" noise).

Design deviation: worker (W10) built a custom `KpiSummary` instead of using the shared `<PixelMetricGrid>` because that component colors negative deltas cadmium — collides with the LED signature. Correct call; LED semantics stay primary.

### Short-query food search fixed
`resolve-ingredient.ts` gained a pre-pass for queries < 8 chars: `ILIKE 'q%'` filtered to `is_canonical=true`. Prefix (not substring) so `oil` doesn't match "b**oil**ed", `salt` doesn't match "without **salt**".

Before/after on prod:
- `egg` → NULL → **Egg white, large** (canonical)
- `rice` → NULL → **Rice, brown, long-grain, cooked**
- `salt` → NULL → **Salt, table**
- `oil` → NULL → **Oil, avocado**
- `oatmeal` → NULL → NULL (canonical row is "Oats, rolled, dry"; needs an alias seed — v0.5.9)

### Migration 029 — the third class of drift, now fixed
`resolve-ingredient.ts` calls two RPCs (`resolve_ingredient_alias_fuzzy`, `resolve_ingredient_food_fuzzy`) that have been silently missing from prod's schema cache since the file was written (v0.4.x). Passes 3 + 4 have been silent no-ops; the only working path was pass 4's error-fallback ILIKE (ordered by `kcal DESC` — completely wrong).

Root cause: RPCs were referenced by the client but never defined in any migration. `verify-migrations-applied` doesn't check `pg_proc` for functions, only tables/columns/indexes. Third class of drift beyond the two we already have safety nets for.

Migration 029 defines both RPCs verbatim (with `SET search_path = public, extensions, pg_temp` for pg_trgm's schema-scoped `similarity()`). Applied to prod. Smoke tests:
- `resolve_ingredient_alias_fuzzy('pollo pechuga')` → `chicken-breast-cooked` (0.81)
- `resolve_ingredient_food_fuzzy('sweet potato')` → **Sweet potato, baked, 1 medium** (0.46)
- `resolve_ingredient_food_fuzzy('chicken breast')` → **Chicken breast, cooked** (0.71)

### LoadErrorCard hoist (v0.5.6 followup)
6 inline copies of the same error card (settings + 5 mini-app pages) → 1 shared component in `@nothing/mini-apps-runtime`. Reconciled real drift during extraction:
- Standardized RELOAD button height: was 36px in some sites, 44px in settings; everyone gets 44px now (matches design brief's touch target).
- Standardized body copy: was raw "{err}" in some sites, full sentence in others; everyone gets "Couldn't load `<thing>`: `<msg>`. This usually means a backend hiccup — try again?"
- Added `thingLabel` prop overrides for natural grammar ("your workouts", "your food log", "your meal plans").

## Lessons

### 1. Three classes of drift, three safety nets

We now know of three ways prod schema can silently diverge from committed code:
- **Class 1 (v0.5.5):** DDL committed to `supabase/migrations/*.sql` but never applied to prod. Fix: `verify-migrations-applied.mjs`.
- **Class 2 (v0.5.7):** Backfill script committed to `scripts/*.mjs` but never run against prod. Fix: `verify-backfills-run.mjs` + `backfill_log` table.
- **Class 3 (v0.5.8):** RPC referenced by `supabase.rpc('name', ...)` in the client but never defined in any migration. Fix: **queued for v0.5.9** — mirror of verify-migrations that introspects `pg_proc` against the union of `.rpc(` call-sites grep'd out of the client.

Every class was discovered the same way: a downstream bug's diagnosis surfaced the drift as a side-effect. The fix pattern is always: (a) fix the immediate bug, (b) build a script that would have caught it, (c) run the script now to find how many other instances exist. Each iteration widens coverage.

### 2. Sharing a component is a discovery mechanism

Extracting `LoadErrorCard` surfaced 5 subtle differences between the 6 inline copies — different button heights, different phrasings, some with disabled states, some without. Nobody had gone looking for these; they'd have persisted forever if the copies had stayed local. Refactoring to share IS the audit step. **Memoed:** when you find a component copied ≥3 times, extract it and treat the reconciliation as a QA pass, not a chore.

### 3. Reject a PRD when the design language demands it

W10's PRD called for `<PixelMetricGrid>` for the KPIs. W10 built a custom `KpiSummary` instead because PixelMetricGrid uses cadmium for negative deltas, which collides with the 2×2 LED signature on `<PixelCard>`. The correct call — the signature is the design language; individual component APIs bend to preserve it. **Memoed:** design-system deviations should be justified by the design system's own rules, not by "cleaner code." Worker was right to push back.

### 4. Dogfooding forces gaps to surface

Building the PROGRESSION tab required using `<PixelLineChart>` in a "cluster of 4 same-shape charts" layout that the assistant never generates. If the component had rigid width assumptions, that would have shown up in this build. It didn't — the 3px-cell fluid grid held up. **Memoed:** the first non-original consumer of a component is a real test of the component's API. Every reusable component needs at least one dogfood-consumer before it can be trusted.
