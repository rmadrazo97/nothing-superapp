# 0.5.2 — Sub-app settings framework + gym HOW-TO + body-comp tracker + PLAN redesign + assistant race fix

**Shipped:** 2026-08-10
**Live at:** https://nothing-superapp.vercel.app

Framework wave. Two reusable component surfaces land (`<MiniAppSettingsPanel>` + `<SwipeableRow>`), one new tracked metric (body composition), one meaningful redesign (Fitness Pal PLAN), and one critical assistant bug fixed at the root.

Shipped in one release across 8 stacked commits from 4 parallel workers coordinated over the 3-concurrent-worker cap:

- Wave A (3 workers, disjoint file sets) — assistant deep-test, settings framework + gym fixes, SwipeableRow component.
- Wave B (3 workers, disjoint file sets) — body composition tracker, Fitness Pal PLAN redesign, assistant race-fix.
- Wave C (main thread) — version bump, changelog, ship note, push, prod verify.

Total elapsed from user's "parallelize" instruction to deploy: ~1h 20m.

## What shipped

### New surfaces
- **`<MiniAppSettingsPanel>` framework** — six components + `useMiniAppSettings<T>(slug, defaults)` hook + migration 020 (`mini_app_settings` jsonb per user × slug) + `/api/mini-app-settings/[slug]` route. Every mini-app can now compose its settings panel from shared primitives instead of hand-rolling 800-line pages. Fitness Pal (823 → 554, 33% shorter) and Reminders (178 → 139) refactored to prove it.
- **`<SwipeableRow>` + `<UndoSnackbar>`** — one gesture pattern, one destructive-action pattern, applied everywhere edit/delete affordances live. Swipe-left OR long-press; ⋯ affordance at 40% opacity; 5s undo window. Keyboard fallback via a visually-hidden menu button. Wired first on the assistant thread drawer, meal-plan cards, and body-metric entries.
- **Shared `<BottomSheet>`** — touch-drag close (~80px threshold), scrim dismiss, Escape. Now used by gym HOW TO + measurements entry form.

### New features
- **Body composition tracker** — new `MEASUREMENTS` tab in Gym. Weekly log for Glutes / Waist / Chest / Thighs / Biceps / Weight, English translation of the Spanish spreadsheet the user shared. Migration 021, canonical integer storage (mm + g) so unit-flip round-trips are lossless. Copilot gets auto-generated CRUD tools via the resource framework.
- **Gym settings** — SECTION 01 · UNITS with WEIGHT (LBS/KG) + LENGTH (IN/CM). First-flip couples KG↔CM and LBS↔IN, independent after.
- **Gym in-session HOW TO** — every exercise on an active session gets a `ⓘ` pill → opens a bottom-sheet with the drawn animation + step-by-step + muscle tags. Same detail render backs both the sheet and the standalone `/exercises/[id]` route.

### Redesigns
- **Fitness Pal PLAN tab** — was "shows only the currently-active plan with a giant red DELETE at the top." Now:
  - **LIST view** — every plan visible, sorted active-first, swipe for EDIT/DELETE
  - **DETAIL view** — DELETE moved into a `⋯` menu (destructive → undo); the three stacked cadmium `RE-LOG AS OPCIÓN 1` CTAs replaced with a compact `+ Log option N` chip (or a ghost `Logged · tap to re-log` when already logged today); 2-column ingredient grid where width allows
  - **CREATE/EDIT** — single-scroll form with macro-split presets (Balanced / High-P / Keto / Custom) + meal→option→ingredient repeaters. Plans are now buildable end-to-end without touching the assistant.

### Fixes
- **Assistant first-message race** — the "laggy and not perfect" complaint. Cold-loading `/app/assistant` and sending a first message was aborting its own SSE stream. Root cause was `<CopilotChat key={threadId ?? 'new'}>` remounting when `threadId` flipped from `null` → `uuid`. Fixed by removing the `key` and adding a self-created-thread guard so the hydrate effect doesn't refetch the empty row over the live stream. Observed ~1:5 fail rate is now 0.
- **Markdown tables** — rendered as raw pipes because `markdown-lite` intentionally skips them. Killed via system-prompt rule ("use paragraphs or bullets"); renderer support deferred to v0.5.3.
- **Header `+ NEW CHAT` collided visually with composer send** — same cadmium color, similar shape, opposite corners → frequent mis-hits. Removed the header duplicate; the drawer entry point remains canonical.
- **"BW" placeholder confusion** — every exercise's weight input showed `BW` regardless of equipment. Now body-weight exercises hide the input + show a "Body weight" pill; weighted exercises show `LBS` / `KG` (from gym settings).

## Lessons

### 1. Parallel workers on disjoint file zones scale cleanly

The 3-concurrent-worker cap held: two waves of 3, zero merge conflicts, zero rework. Key discipline was declaring safe zones IN EACH worker's prompt with explicit "do NOT touch" lists naming the other workers' files. When Worker A2 finished a shared file (`gym-routine/page.tsx` — a tab addition), Worker B1 read the fresh state before appending its own tab addition. No file-serialized locks needed; the prompt was the coordination.

### 2. `<CopilotChat key={threadId}>` was the whole "assistant is laggy" complaint

Worker A1's deep-test report was worth its dispatch just for this. What looked like backend/model latency was a 15-line client bug — a `key` prop on `CopilotChat` that tore down the SSE mid-stream. Backend p50 first-token: ~800-1500ms (perfectly fine). Client-perceived: user's bubble disappeared, response never arrived, 1-in-5 sends orphaned an empty "New chat" row.

Also: passing `useChat({ id })` would have had the same problem — the SDK's internal `Chat` instance is also recreated on `id` change. The fix was NOT "use the SDK's stable id"; it was "don't remount at all, and guard the hydrate effect from self-triggering." Worker B3 caught the SDK gotcha by reading `node_modules/@ai-sdk/react/dist/index.js:326` before implementing.

### 3. Report-only workers are cheap and load-bearing

Task #87 spent one worker on read-only exploration + a written report. No code, no risk of stomping other work — but the report drove the entire assistant fix wave (task #93) and would have taken 3× longer to diagnose from inside a fix loop.

### 4. Canonical integer storage beats display units on-disk

Body metrics stores mm (measurements) + g (weight), not inches / lbs. A user who logs `12.5 in` sees `12.5 in`, flips to CM, sees `31.75 cm`, flips back, sees `12.5 in` — no float drift, no lossy conversions on read/write. The 8 conversion helpers in `@nothing/shared/schemas/gym.ts` are all null-pass-through so partial entries work.
