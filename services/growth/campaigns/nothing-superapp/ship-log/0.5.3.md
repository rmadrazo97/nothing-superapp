## What shipped

### Assistant reliability
- **The real first-message race fix.** B3's v0.5.2 attempt removed the outer `key={threadId}` remount but missed that `CopilotChat.tsx` was also rebuilding `DefaultChatTransport` on every `threadId` change via `useMemo(..., [context, threadId])`. The AI SDK swaps its internal `Chat` instance when the transport ref changes → same net effect as a `key` remount, aborts the SSE mid-first-message. P1's diagnosis was static-analysis + SDK-source verification (`node_modules/@ai-sdk/react/dist/index.js:326` and `HttpChatTransportInitOptions` type). Fix: transport stable across renders; dynamic `thread_id` + `timezone` travel via `prepareSendMessagesRequest` reading a `threadIdRef` at request time.
- **Timezone.** Client sends the browser's IANA tz on every `/api/copilot` request; server injects "USER TIMEZONE + current local wall-clock" into the system prompt. "Remind me in 10 min" now schedules against YOUR clock, not UTC.
- **Tool idempotency.** `computeIdempotencyKey(tool + input + user + floor(ts/30s))` + `ON CONFLICT DO NOTHING` on a partial unique index. Wired to `create_reminder` + `log_calorie_entry`; other write tools follow in v0.5.4 (task #108).

## Lessons

### 1. Deep diagnoses beat surface fixes

B3's v0.5.2 assistant fix removed the visible `key` prop but missed the transport-recreation path one level below. The bug survived to v0.5.2 prod and Alex hit it immediately. P1's fix required reading the SDK source (`node_modules/@ai-sdk/react/dist/index.js`) to confirm that passing `id` to `useChat` would ALSO cause the remount (was ruled out) and then finding the transport `useMemo` dep. Memoed as: when a race "fixed" in one commit reappears in prod, don't ship a second surface patch — read the framework source.

### 2. 3-worker cap held again through 2 more phases

Phase 1's 3 parallel workers had one legitimate file overlap (both P1 and P3 wanted `apps/web/src/app/app/settings/page.tsx` — P1 for TIMEZONE field, P3 for changelog disclosure). Explicit "P1 owns Profile section, P3 owns Changelog section" language in each brief was enough — P1 ended up committing both edits atomically (P3 had staged both, P1 picked them up). Zero collisions, one merge-clean commit.

### 3. The `/frontend-design` skill made D3's second pass distinctive

B3's first PLAN redesign got a "this is horrible" from Alex despite hitting spec. D3's second pass via `/frontend-design` (brainstorm→plan→critique→build→critique-again) landed the RX-slip metaphor + MacroTape signature that read as intentional. Skill's discipline against AI-templated defaults ("warm cream + terracotta + big serif" / "near-black + acid-green accent" / "broadsheet hairline columns") pushed us to a specific-to-Nothing-Superapp direction.

### 4. Food-search rank is a product decision, not a data problem

USDA SR Legacy (7,946 rows) has every industrial variant + regional obscurity. Fresh install with default sort → "Sweet potato" search leads with 5+ babyfood variants before the actual `Sweet potato, baked, 1 medium`. Fix wasn't schema — it was policy: `is_canonical` boolean + demotion patterns + a 251-entry curated seed (sourced from USDA MyPlate common foods + hand-curation). This shape is generalizable — any large-ish domain dataset (foods, exercises, brands) needs a canonical-subset layer between the raw data and search.

### 5. Chrome is not free

Alex's screenshot-driven feedback ("this is horrible", "too tall", "too narrow", "the loading spinner is horrible", "this makes no sense") pushed the app toward more density in every direction: killed the ASK chip, killed the WATER tab, compacted the streak card, shrunk the CTA, widened the message column, moved DELETE from header to menu. Every square pixel of chrome above the tab bar competes with content. Repeated small subtractions add up to a "feels more designed" result more reliably than any single big rewrite.
