## What shipped

- **Class 1 drift** (DDL committed but not applied) — `verify-migrations-applied.mjs` (v0.5.5)
- **Class 2 drift** (backfill script not run) — `verify-backfills-run.mjs` (v0.5.7)

Every known way for prod schema to silently diverge from committed code now has a CI job that would catch it in the release that introduces it. Each job SKIPs cleanly on misconfig (so bad secrets can't clog CI red) and reports real drift as `[MISS]` + exit 1.

## Lessons

### 1. Safety-net completeness is a discovery process, not a design step

At v0.5.5 we thought verify-migrations-applied was "the" safety net. v0.5.6 discovered a whole other class of drift (backfills-not-run). v0.5.8 discovered another (RPCs-not-defined). v0.5.9 finally covers all three. **Memoed:** you can't design the complete taxonomy of drift classes upfront — new ones surface each time a downstream bug forces a diagnosis. Ship each safety net as its own release + write down what it caught + let the next incident tell you what's missing.

### 2. Workflow linting should happen before every commit

`security-advisor.yml` had a bug that broke every run for a full release cycle. Would have been caught by `actionlint` on the pre-commit that introduced it. **Memoed:** add `actionlint` to the pre-push hook (or a CI validation step). Any workflow that doesn't parse should fail before it merges, not after 6 mysteriously-red runs.

### 3. Curated whitelists need a "missed-demand" check as their companion

canonical-foods.json is a hand-curated whitelist. It's easy to add entries that hit rows; harder to know which important queries are still missing. W15's extension of `audit-canonical-patterns.mjs` compares the JSON against a 73-query "top daily-log queries" list — any query that doesn't have a canonical hit surfaces as missed demand. Ran once, found 7 more gaps (all filled by mig 030 aliases). **Memoed:** every hand-curated dataset needs an inverse "did we miss anything obvious?" check, or drift accumulates silently.

### 4. Autonomy compounds: 6 releases in 8 hours

v0.5.4 (generative UI) → v0.5.9 (this release) shipped in ~8 hours with 15 parallel workers across 5 waves. Zero merge conflicts. Every wave landed the same way: 3 workers on disjoint file zones, all commit locally, wave-Z bumps version + writes ship-log + pushes + broadcasts. **Memoed:** the pattern is durable. The disjoint-zone brief is the whole trick — never let two workers touch the same file, and coordination overhead drops to zero.
