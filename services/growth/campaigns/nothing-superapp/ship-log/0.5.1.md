## Lessons

### 1. Emoji tile icons are the locked direction

A prior worker attempted to unify the launcher icons to flat monochrome geometric glyphs (`◐ ◔ ◈ ◇ ◑`). It looked "designed" but the user reversed the decision — the emoji tiles read as friendlier and don't blur the brand line between OS-chrome (SVG) and product-surface (emoji). Memoed as `feedback_ns_tile_icons_use_emoji.md`. Future workers: do not attempt to unify again.

Corollary: chrome elements — nav bar, cog buttons — still use minimalist SVG/text glyphs. Two different visual systems, on purpose.

### 2. The ⚙ unicode glyph is not a text glyph on iOS/macOS

Safari on Apple platforms renders bare `U+2699 GEAR` as the OS's colorful gear icon. To force text-glyph presentation append `U+FE0E VARIATION SELECTOR-15` — the resulting `⚙︎` (5 bytes UTF-8) is a plain monochrome glyph that respects `color: currentColor`. Learned by inspecting real device screenshots — the JSX source `⚙` looked fine in editor but rendered as the macOS graphic in-app.

### 3. `?next=` open-redirect defence

Any `?next=<path>` param that leaves user-controlled input on the URL needs an allow-list on both the middleware AND the callback endpoint. The safe pattern: reject absolute URLs (must start with `/`), reject protocol-relative (`//host/x`), require a same-origin path prefix from a short allow-list (`/app`, `/paywall` here). `lib/safe-next.ts` is the single implementation both sides call.

### 4. Registry ordering isn't always alphabetical

`registry.ts` sorts by slug for real mini-apps but the coming-soon placeholder is deliberately appended LAST. Add-only convention on shared files works well when combined with a stable ordering rule; alphabetical is the default, but not the law.
