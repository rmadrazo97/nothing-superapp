1. Thesis §

The average consumer pays five separate subscriptions for utility apps that don't talk to each other. A calorie tracker at $4.99, a workout logger at $9.99, a pomodoro timer at $2.99, a chat AI at $20 — none of which know that the other exists. The user re-enters the same information across five surfaces, and the models across five surfaces never once cross-reference.

Nothing Superapp collapses the stack: one shell, one subscription, one AI that reads across every mini-app you touch. Adding a new mini-app is a folder plus six lines of glue. The AI copilot's context is auto-assembled from every table the mini-apps write to. You pay $1 a month instead of $37.97.

The thesis isn't "app store 2.0." It's "the copilot is the app, and the mini-apps are its senses."

3. The four mini-apps §

◐

Calorie Lite

Nutrition tracking with macros, streaks, and a weekly trend sparkline. The v1 was a reference implementation — kcal only, three views, a running total. v2 surfaces the macros the schema was already storing but the UI wasn't showing. Add gets three optional inputs (protein / carbs / fat). Today gets a MacroCard under the kcal card. History gets an inline-SVG sparkline with a dashed target line and a streak counter that has morning-grace — if today has no entries yet, the walk starts from yesterday so the counter doesn't flicker to 0 every morning before breakfast.

  • Kcal + P/C/F per entry, per day, per week
  • Streak: current + best, morning-grace, DST-safe date shifting
  • Sparkline: inline SVG, 7-day bars, dashed target line
  • Backward compatible: v1 entries (all-zero macros) suppress the per-entry macro line to avoid distraction
◈

Gym Routine

1,324 exercises with animated form GIFs, live sessions with a rest timer, routines you can save and re-run. Data seeded from the open exercises-dataset (MIT data + Gym Visual media with attribution baked in). 6 pages, 7 API handlers, 3 new Supabase tables. The exercise browser debounces search, cancels stale requests by request-id, paginates 60 at a time. The live session's rest timer uses requestAnimationFrame + Date.now diffing — no drift under tab sleep or throttling. Server owns ended_at; client PATCHes {end:true}, server stamps now() — no client-clock trust.

  • 1,324 exercises · 10 body parts · 28 equipment types
  • Live session with rest timer + volume tracking
  • Cross-device resume: partial index on (user_id) where ended_at is null keeps GET /sessions/live O(1)
  • Animated GIFs lazy-loaded on detail pages only — browse grid uses static thumbnails
  • Gym Visual attribution rendered on every detail page (non-negotiable per license)
◔

Pomodoro

Classic 25/5/15 cycle with a Date.now-accurate timer that survives tab switches. The timer stores endTs = Date.now() + duration and recomputes remainingMs = endTs - Date.now() on every render. setTimeout(250ms) only exists to trigger re-renders — the clock is math, not a decremented counter. sessionStorage mirrors the end timestamp so a reload during a running session restores the exact wall-clock finish time. WebAudio two-tone chirp on phase transition (lazily instantiated inside a user-gesture chain to satisfy Safari's autoplay policy). Skip logs an aborted session for auditability; Reset discards.

  • Work / short break / long-every-4th cycle, all durations user-editable
  • Timer survives tab throttle, sleep, reload
  • WebAudio beep, Safari-safe
  • Daily streak dots + focus history
◊

Copilot (Kimi K2)

Streaming AI chat that reads across every mini-app you touch. Uses the OpenAI-compat SDK pointed at Moonshot's endpoint. The context assembler reads profile + preferences + last 20 calorie entries + last 20 events + last 5 workout sessions + last 5 saved routines + a 7-day pomodoro summary + the last 3 individual pomodoros — all through the user's authenticated Supabase client so RLS enforces owner-scoping. Round-robin truncation across the four mini-app row lists so we shrink evenly at the 6000-char cap instead of nuking one dimension. Kimi K2's reasoning_content deltas arrive before content; we forward both on separate SSE frames so the UI can render them in a collapsed disclosure. System prompt names every mini-app's data key so the model can cite by name.

  • Kimi K2 (kimi-k2.6) via OpenAI-compat SDK
  • SSE streaming, reasoning tokens on a separate frame
  • Cross-mini-app context, hard-capped, round-robin truncated
  • Read-only — no writes to any table, ever

4. The copilot moment §

This is the pitch that only a superapp can make. You can ask something like:

Given last night's sleep, my calorie deficit, and the leg day I did yesterday — is it smart to run 10k tomorrow?

And the model cross-references workout_sessions, app_calorie_entries, and preferences.daily_calorie_goal to answer:

Skip it. Heavy leg volume yesterday (45min, 12 sets) plus a -400 kcal daily deficit. Recovery will be under-fueled. Cap at 5k easy pace if you must. Or add 800 kcal from carbs today and reassess tomorrow morning.

No third-party integrations. No OAuth to eight external services. Just the tables the mini-apps write to, streaming through Kimi K2 with reasoning tokens visible on demand.

6. The build pattern §

The whole thing was built using a 7-phase pattern (Size → Clarify → Spec → Decompose → Approve → Execute → Deliver) with parallel Sonnet workers dispatched wave-by-wave and durable state on disk under docs/dev-loop/<slug>/. The pattern's superpower is that the state survives chat compaction — a stalled feature can be resumed three days later without losing context.

The v0.1 harness was 14 tasks in 6 waves. The v0.2 mini-app expansion was 3 tasks in 2 waves (pomodoro + gym-routine parallel, then calorie-lite v2 solo). Every worker committed nothing directly — the orchestrator batch-committed each wave with a full context-aware commit message.

Wave discipline

  • Each wave has 1–3 workers, never more than 3 (past that, prompt discipline breaks down).
  • Shared registration files (schemas, client-registry, next.config, package.json) use an "add-only, never remove" convention — parallel edits are safe because appends compose.
  • Migration files stay separate per worker (002_pomodoro.sql, 003_gym.sql) — merges are safer at the FS level than the text level.
  • Every worker gets an explicit "you own X, others own Y" boundary. If a boundary gets crossed, the diff review at commit time catches it.

7. Lessons §

What worked

  • Locking the design tokens on day one. Zero hex codes in the shipped app. Every mini-app inherits the same visual language because there's no other option — the escape hatches (raw hex) are grep-tested at DoD.
  • File-convention registry. Adding gym-routine (2,700 lines) required zero orchestrator plumbing — just a manifest and a one-line re-export. The AI grep tools even found the pattern without being told.
  • Server-owned timestamps. Gym's ended_at, calorie's entered_at, pomodoro's ended_at — all server-stamped. Client's clock is untrusted. Prevents backdating, timezone drift, and the "user changed their phone time" edge case.
  • Round-robin context truncation. When the copilot's assembled JSON hits the cap, we trim the tail of whichever mini-app list is currently longest. Prevents "the model only saw calorie entries because they were newest."

What didn't

  • The --space-5 gap. Three separate workers reached for a spacing token that doesn't exist (the scale skips 5 and 7 by design). Each burned an escape-hatch turn discovering it. Now surfaced in every prompt.
  • Race with Turbopack on runtime import(). The mini-app registry couldn't use dynamic import to load manifests because Turbopack can only bundle statically analyzable specifiers. Switched to a paren-balanced source parse — bundler-agnostic, testable, works everywhere.
  • Stripe webhook race. On the golden-path e2e we caught a duplicate stripe_customer_id constraint violation when a webhook event arrived twice with different customer IDs for the same user. Non-fatal (idempotent handler recovered) but worth logging as a follow-up.
  • Google OAuth still needs a provider config. Client code is wired, but the button will error until a Google Cloud OAuth client is created and pasted into the Supabase dashboard. Magic-link works out of the box.

8. What's next §

Three tracks, roughly in priority order:

  1. Native shells via Capacitor — the same Next.js codebase wraps to iOS + Android. Same shell, same auth, same paywall, same copilot. Zero mini-app rewrites.
  2. More mini-apps — a habit tracker (5 tables of data + 1 mini-app UI), a notes / journal (single free-text row per day), a water tracker (increment button, daily target). Each is a folder plus six lines of glue.
  3. Copilot writes — right now the AI is read-only. Making it call bounded write endpoints (log a meal, start a workout, add a habit) turns it into an actual assistant, not just a query engine. Needs a careful tool-use surface with per-tool confirmation.

The v0.2 shipped. Everything above is v0.3 or later.
