# Folder Conventions -- per target

Draw the actual folder tree in the blueprint. Copy the applicable section, adjust for the user's stack picks.

Rules across all conventions:
- No file/folder over 3 levels deep unless there's a strong reason.
- Kebab-case filenames, PascalCase for React components.
- Colocate: tests next to source, types next to models.
- ALWAYS have a `README.md` at the repo root and a `.env.example` if env vars are used.

---

## Convention 1: Next.js 16 App Router (single-target web/PWA)

```
my-app/
├── src/
│   ├── app/                          # App Router entry
│   │   ├── (marketing)/              # public routes group (layout: marketing)
│   │   │   ├── page.tsx              # / (landing)
│   │   │   ├── about/page.tsx
│   │   │   └── layout.tsx
│   │   ├── (app)/                    # authenticated routes group
│   │   │   ├── dashboard/page.tsx
│   │   │   ├── settings/page.tsx
│   │   │   └── layout.tsx            # auth guard here
│   │   ├── api/                      # Route Handlers
│   │   │   ├── auth/[...supabase]/route.ts
│   │   │   └── webhooks/stripe/route.ts
│   │   ├── globals.css
│   │   └── layout.tsx                # root
│   ├── components/
│   │   ├── ui/                       # shadcn primitives (do not hand-edit)
│   │   └── features/                 # feature-specific (Composable, feature-owned)
│   ├── lib/
│   │   ├── db.ts                     # Drizzle client
│   │   ├── auth.ts                   # Supabase auth helpers
│   │   ├── stripe.ts
│   │   └── utils.ts                  # cn(), formatters
│   ├── stores/                       # Zustand
│   ├── hooks/                        # custom React hooks
│   ├── drizzle/
│   │   ├── schema/                   # one file per table
│   │   └── migrations/               # generated
│   └── types/                        # global TS types
├── public/                           # static assets, PWA manifest
├── tests/                            # e2e (Playwright); unit tests colocated as *.test.ts
├── .env.example
├── drizzle.config.ts
├── next.config.ts
├── tailwind.config.ts
├── package.json
└── README.md
```

Naming:
- Pages: `page.tsx` (App Router convention).
- Components: `PascalCase.tsx`.
- Route Handlers: `route.ts`.
- Helpers: `kebab-case.ts`.
- Tests: `*.test.ts` colocated with source.

## Convention 2: PWA (Next.js) + Capacitor native shells (multi-target)

```
my-app/
├── apps/
│   └── web/                          # ← Recipe 1 structure lives here
│       ├── src/...
│       ├── public/
│       ├── capacitor.config.ts       # Capacitor points at web build output
│       ├── ios/                      # generated by `npx cap add ios`
│       ├── android/                  # generated by `npx cap add android`
│       └── package.json
├── packages/
│   ├── shared/                       # code shared web + native
│   │   ├── src/
│   │   │   ├── design-system/        # tokens, styles.css (from design-system-builder)
│   │   │   ├── types/                # shared TS types
│   │   │   ├── schemas/              # Zod schemas (shared client + server)
│   │   │   └── api-client/           # typed API wrapper
│   │   └── package.json
│   └── config/                       # shared tsconfig, eslint, prettier
├── docs/
│   ├── architecture/stack-blueprint.md   # ← the blueprint this skill produces
│   └── prd.md
├── pnpm-workspace.yaml
├── package.json
└── README.md
```

Naming: same as Convention 1 inside `apps/web/`. Shared packages named after purpose (`shared`, `config`, `ui-primitives`), not team.

## Convention 3: Cloudflare Workers + Pages (edge-first)

```
my-app/
├── apps/
│   └── web/                          # Next.js (or Astro) frontend
│       └── ...
├── workers/
│   ├── api/                          # main Hono API worker
│   │   ├── src/
│   │   │   ├── index.ts              # Hono app entry
│   │   │   ├── routes/               # one file per route group
│   │   │   ├── middleware/
│   │   │   └── db/                   # Drizzle schema + client
│   │   ├── wrangler.toml
│   │   └── package.json
│   └── webhooks/                     # separate worker for webhooks (better cold-start isolation)
├── packages/shared/                  # shared types + schemas
├── migrations/                       # D1 SQL migrations
└── ...
```

Naming: workers named by purpose (`api`, `webhooks`, `cron`), one worker per major responsibility.

## Convention 4: Expo (React Native, native-first)

```
my-app/
├── app/                              # Expo Router file-based routing
│   ├── (tabs)/
│   │   ├── index.tsx                 # home tab
│   │   ├── settings.tsx
│   │   └── _layout.tsx               # tab bar layout
│   ├── (auth)/
│   │   ├── sign-in.tsx
│   │   └── _layout.tsx
│   ├── _layout.tsx                   # root
│   └── +not-found.tsx
├── components/                       # PascalCase.tsx
├── lib/
│   ├── supabase.ts
│   └── stripe.ts
├── hooks/
├── constants/                        # colors, tokens, config
├── assets/                           # images, fonts, icons
├── app.json                          # Expo config
├── eas.json                          # EAS Build config
├── metro.config.js
├── tsconfig.json
├── package.json
└── README.md
```

Naming: Expo Router uses file names for URLs (`(group)`, `_layout.tsx`, `+not-found.tsx` are conventions).

## Convention 5: SwiftUI iOS-only

```
MyApp/
├── MyApp/
│   ├── MyAppApp.swift                # @main entry
│   ├── ContentView.swift
│   ├── Views/                        # one file per view, PascalCase
│   │   ├── Home/
│   │   ├── Settings/
│   │   └── Onboarding/
│   ├── Models/                       # @Observable state
│   ├── Services/                     # SupabaseClient, StoreKit wrapper
│   ├── Extensions/
│   ├── Resources/
│   │   ├── Assets.xcassets
│   │   └── Localizable.strings
│   └── Info.plist
├── MyAppTests/                       # XCTest unit tests
├── MyAppUITests/                     # XCUITest UI tests
├── MyApp.xcodeproj/
├── Package.swift                     # if using SPM for shared modules
└── README.md
```

Naming: Swift convention — PascalCase for types, camelCase for functions/vars.

## Convention 9: Monorepo (pnpm workspaces) for multi-target

Top-level structure any of the above can nest under:

```
my-project/
├── apps/                             # deployable applications
│   ├── web/                          # Next.js PWA
│   ├── mobile/                       # Expo native (if separate codebase)
│   ├── api/                          # Hono API
│   └── docs/                         # marketing site
├── packages/                         # shared libraries
│   ├── ui/                           # component primitives
│   ├── shared/                       # types, schemas, utils
│   ├── config/                       # tsconfig, eslint, prettier presets
│   └── design-system/                # from design-system-builder
├── docs/                             # architectural docs
│   ├── architecture/
│   │   ├── stack-blueprint.md        # ← this skill's output
│   │   └── prd.md
│   └── runbooks/
├── .github/workflows/
├── pnpm-workspace.yaml
├── turbo.json                        # if using Turborepo for task orchestration
├── package.json
└── README.md
```

Rule of thumb: apps = deployable, packages = importable.
