# Credentials Catalog -- what each service needs

For every service we recommend, this file lists: signup URL, whether it needs a payment method to sign up, what env vars/keys it produces, and any one-time dashboard config. Use this to generate the § 11 Prerequisites section of the blueprint.

Update whenever a service changes its onboarding flow or key names.

---

## GitHub

- **Signup:** https://github.com/join
- **Payment method at signup:** No (unlimited public repos free; 1 private with unlimited collaborators free; Actions 2k mins/mo free).
- **Produces:** GitHub account + username + personal access token if scripting.
- **Env vars (typical):** `GH_TOKEN` for gh CLI or Actions checkout (optional).
- **Config steps:** Create org (if team), create repo, add secrets under Settings → Secrets → Actions.

## Vercel

- **Signup:** https://vercel.com/signup — sign in with GitHub.
- **Payment method:** No (Hobby is free forever).
- **Produces:** Vercel account linked to GitHub, project auto-deploys.
- **Env vars (typical):** `VERCEL_TOKEN` if scripting deploys.
- **Config steps:** Link GitHub repo → Vercel auto-deploys on push to main + previews per PR. Add all `.env.local` keys under Project Settings → Environment Variables (mark production / preview / development scopes).
- **Watch:** Hobby is "personal use only" per ToS — upgrade to Pro ($20/mo) before real users hit the app.

## Supabase

- **Signup:** https://supabase.com/dashboard/sign-in — sign in with GitHub.
- **Payment method:** No (Free tier: 2 projects, 500MB DB, 5GB egress, 1GB storage, unlimited MAU).
- **Produces:** Project URL + `anon` public key + `service_role` secret key + DB connection string.
- **Env vars:**
  - `NEXT_PUBLIC_SUPABASE_URL` — project URL (e.g. `https://xyz.supabase.co`)
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — public anon key (safe in client)
  - `SUPABASE_SERVICE_ROLE_KEY` — bypasses RLS, server-side only, never expose to client
  - `DATABASE_URL` — Postgres connection string for Drizzle migrations
- **Config steps:**
  - Choose region closest to primary users (matters for latency).
  - Enable OAuth providers under Auth → Providers (paste Google/Apple credentials from below).
  - Set redirect URLs (`http://localhost:3000/api/auth/callback`, `https://your-domain.com/api/auth/callback`).
  - Create tables + RLS policies (Drizzle handles table creation; RLS policies via Supabase SQL editor or migrations).

## Stripe

- **Signup:** https://dashboard.stripe.com/register
- **Payment method:** No for test mode; yes to accept live payments (requires business info).
- **Produces:** `sk_test_*` / `sk_live_*` secret keys + `pk_test_*` / `pk_live_*` publishable keys + webhook signing secret.
- **Env vars:**
  - `STRIPE_SECRET_KEY` — server-side
  - `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` — client-side
  - `STRIPE_WEBHOOK_SECRET` — validates incoming webhooks
- **Config steps:**
  - Create products (monthly + annual subscription).
  - Note the `price_*` IDs — these go into your checkout URL.
  - Configure webhook endpoint (post-deploy): `https://your-domain.com/api/webhooks/stripe` → listen to `checkout.session.completed`, `customer.subscription.created|updated|deleted`, `invoice.payment_succeeded|failed`.
  - Enable Apple Pay + Google Pay under Payment Methods for PWA checkout.

## RevenueCat

- **Signup:** https://app.revenuecat.com/signup
- **Payment method:** No (free up to $2.5k tracked MTR / mo).
- **Produces:** App-scoped public API keys (per platform) + webhook secret + entitlement config.
- **Env vars:**
  - `NEXT_PUBLIC_REVENUECAT_APPLE_API_KEY` — iOS client
  - `NEXT_PUBLIC_REVENUECAT_GOOGLE_API_KEY` — Android client
  - `REVENUECAT_WEBHOOK_SECRET` — server-side webhook validation
- **Config steps:**
  - Create project → add iOS app (bundle ID) + Android app (package name).
  - Import products from App Store Connect + Google Play Console (auto after they're set up).
  - Create Entitlement "premium" → attach both iOS + Android products.
  - Configure webhook (post-deploy): `https://your-domain.com/api/webhooks/revenuecat` for subscription lifecycle events.

## Apple Developer Program

- **Signup:** https://developer.apple.com/programs/enroll/ (individual or business).
- **Payment method:** Yes — **$99/yr**.
- **Produces:** Team ID + certificates + provisioning profiles + Sign in with Apple credentials + StoreKit access.
- **Env vars (for Sign in with Apple server-side):**
  - `APPLE_TEAM_ID` — 10-char team ID
  - `APPLE_KEY_ID` — 10-char key ID
  - `APPLE_PRIVATE_KEY` — .p8 file contents (paste literally, includes BEGIN/END lines)
  - `APPLE_CLIENT_ID` — Services ID reverse-DNS (e.g. `com.yourapp.web`)
- **Config steps:**
  - Enroll → wait 24-48 hours for approval.
  - App Store Connect: create app record (bundle ID, name, category).
  - Certificates, IDs & Profiles: create Services ID (for web-based Sign in with Apple) + Key for Sign in with Apple.
  - Configure return URLs: `https://your-domain.com/api/auth/callback`.

## Google Play Console

- **Signup:** https://play.google.com/console/signup
- **Payment method:** Yes — **$25 one-time**.
- **Produces:** Play Console access, app publishing capability, Play Billing integration.
- **Env vars:** None client-side; Play Billing keys go into Google Play Console → In-app products.
- **Config steps:**
  - Create app record → complete Store Listing → set up Internal Testing track.
  - Create in-app products matching Stripe products (same duration + price).
  - Link to RevenueCat via service account.

## Google Cloud (for Sign in with Google OAuth)

- **Signup:** https://console.cloud.google.com/ (free with Google account).
- **Payment method:** No for OAuth (only if using paid Google Cloud services).
- **Produces:** OAuth 2.0 Client ID + Client Secret.
- **Env vars:**
  - `GOOGLE_OAUTH_CLIENT_ID`
  - `GOOGLE_OAUTH_CLIENT_SECRET`
- **Config steps:**
  - Create project → APIs & Services → OAuth consent screen → configure (app name, support email, scopes).
  - Credentials → Create OAuth Client ID → Web application.
  - Authorized redirect URIs: `http://localhost:3000/api/auth/callback`, `https://your-domain.com/api/auth/callback`, and the Supabase Auth callback URL (paste from Supabase Auth → Providers → Google).

## Resend

- **Signup:** https://resend.com/signup
- **Payment method:** No (free: 3k emails/mo, 100/day, 1 sending domain).
- **Produces:** API key + verified sending domain.
- **Env vars:** `RESEND_API_KEY`
- **Config steps:**
  - Add sending domain (subdomain like `mail.yourapp.com` recommended).
  - Add DNS records shown (SPF + DKIM) — TTL up to 24h. Verify status turns green before sending.

## PostHog

- **Signup:** https://us.posthog.com/signup (US-hosted) or https://eu.posthog.com/signup (EU-hosted for GDPR).
- **Payment method:** No (free: 1M events/mo, 15k session replays, 1M feature flag requests).
- **Produces:** Project API key + host URL.
- **Env vars:**
  - `NEXT_PUBLIC_POSTHOG_KEY` — project API key (safe in client)
  - `NEXT_PUBLIC_POSTHOG_HOST` — `https://us.i.posthog.com` or `https://eu.i.posthog.com`
- **Config steps:**
  - Create project → note the key.
  - Configure privacy: enable session-recording masking of `input[type="password"]` + any custom PII selectors.
  - (Recommended) Set up reverse proxy in Next.js: create `next.config.ts` rewrite `/ingest/*` → `https://us.i.posthog.com/*` to bypass ad-blockers. Then `posthog.init(key, { api_host: '/ingest' })`.
  - Define first-week event names in the Insights → Events dictionary so the team uses consistent names.

## Sentry

- **Signup:** https://sentry.io/signup/
- **Payment method:** No (free: 5k errors + 10k performance + 500 replays / mo).
- **Produces:** DSN per project + auth token for source-map uploads.
- **Env vars:**
  - `SENTRY_DSN` — public DSN (safe in client)
  - `SENTRY_AUTH_TOKEN` — for CI upload of source maps
  - `SENTRY_ORG` + `SENTRY_PROJECT` — for CLI
- **Config steps:**
  - Create project → pick Next.js template → run `npx @sentry/wizard@latest -i nextjs` (writes config files).
  - Enable performance monitoring for tRPC / Route Handler traces.
  - Configure release tracking via CI (auto-includes commit SHA).

## Cloudflare Registrar (domain)

- **Signup:** https://dash.cloudflare.com/sign-up (free account).
- **Payment method:** Yes for domain purchase (**~$10-15/yr at-cost pricing** for most TLDs).
- **Produces:** Domain, DNS management, optional Cloudflare CDN in front.
- **Env vars:** None (DNS is managed in the dashboard).
- **Config steps:**
  - Register domain (or transfer existing).
  - Point NS to Vercel: Cloudflare → DNS → set nameservers to Vercel's if using Vercel-managed DNS, OR keep Cloudflare DNS and add CNAME to Vercel's target.
  - Verify domain in Vercel → Project Settings → Domains.

## Anthropic (Claude API)

- **Signup:** https://console.anthropic.com/ (free account, requires payment method for prod usage).
- **Payment method:** Yes to send production API calls (pay-as-you-go). Free credit for testing.
- **Produces:** API key.
- **Env vars:** `ANTHROPIC_API_KEY`
- **Config steps:**
  - Create workspace + API key.
  - Set spend limit (recommended) to prevent runaway costs.
  - Enable prompt caching for repeated system prompts.

## Blueprint substitution: how to fill § 11 from this catalog

For each service in the locked stack, emit ONE row in the accounts table and ONE row in the env-vars table. Example:

```markdown
### 11a. Accounts to create

| Service | Signup | Payment method at signup? | Free tier |
|---|---|---|---|
| GitHub | https://github.com/join | No | 1 private repo, 2k Actions mins/mo |
| Vercel | https://vercel.com/signup | No | Hobby: 100GB bandwidth/mo |
| Supabase | https://supabase.com/dashboard/sign-in | No | 500MB DB, unlimited MAU |
| ...(one per locked service)... |
```

The `PREREQ_ACCOUNTS`, `PREREQ_ENV_VARS`, `PREREQ_LOCAL_DEV`, and `PREREQ_CONFIG_STEPS` placeholders take markdown blocks; format them as tables or nested lists per convention above.
