## 🔁 Worker turn protocol — READ FIRST, RUN EVERY TURN

This is the operating manual. Every worker turn starts here.

**0.** Check `docs/dev-loop/{{FEATURE_SLUG}}/status.json` — if your task is flagged `drift`, diff `spec.md` against the `spec_version_at_dispatch` in this frontmatter before proceeding. Watch mode may have amended requirements silently.

**1. Re-read** `docs/dev-loop/{{FEATURE_SLUG}}/spec.md` AND this task file (top to bottom). Watch mode may have amended them mid-flight. **This is not optional; drift is silent.** If `spec.md` header shows a `spec_version` newer than this task's `spec_version_at_dispatch`, discard any in-progress plan and re-plan from the new spec.

**2. Re-read your own last entry in `progress.md`** — confirm you're not repeating work.

**3. Pick the next unmet acceptance criterion** (see § "Acceptance criteria" below) and the single hunk that satisfies it. One criterion, one commit-worthy change per turn.

**4. Make the change, run the DoD command's most-relevant slice.** Every 3rd turn, run the FULL DoD command (not just the slice) to catch integration drift.

**5. Append to `progress.md`** with a `## Task {{TASK_ID}} — turn N — <timestamp>` block containing:
   - What changed (files + hunks)
   - Which acceptance criterion is now met
   - `read_spec_version: N` (echo the spec version you worked against)
   - What remains

**6. If DoD passes fully**: STOP, mark yourself done, exit.

**7. If stuck 2× on the same failure**: consult the advisor per triggers below.

**8. Otherwise**: continue to next turn — but stop at max_worker_turns OR max_wall_clock_min OR max_judge_fail_streak, whichever hits first.

## 🛑 STOP — Escape hatch (READ SECOND)

From `codex-first`'s lesson: a cornered worker satisfies the letter of the gates and cheats the spirit. Every hard constraint below has a sanctioned STOP-and-report. **Stop-reports are successful runs.** Working around a constraint is a failed run the judge WILL catch.

If ANY of these blocks you from making honest progress: STOP, write exact diagnosis to `progress.md`, exit — do NOT work around.

- **Owned surface / off-limits violation** would be needed to complete task → STOP, report "task needs to touch <path> which is off-limits because <reason from spec>". Do NOT touch it.
- **DoD command is unrunnable** (missing script, wrong path, broken assertion) → STOP, report "DoD command references <thing> which doesn't exist / doesn't work". Do NOT modify the DoD command to make it pass.
- **Reusable pattern doesn't fit** (spec says reuse X, but X's shape is wrong for this case) → STOP, report "reusable pattern X does not fit because Y". Do NOT silently duplicate it.
- **Acceptance criterion is untestable as written** (vague, unfalsifiable, contradicts another) → STOP, report the ambiguity. Do NOT reinterpret it to be trivially true.
- **A hard prohibition would force you to** minify identifiers / delete tests / narrow criteria / modify orchestrator files (`spec.md`, `tier-config.yaml`, `deps.json`, other tasks) → STOP. These are structural signals that scope is wrong, not that the rules are wrong.
